# Письма для Даши

Мобильный квест в иллюстрированном зимнем доме: три комнаты по пять тайников, ступенчатые подсказки, сохранение после каждого действия. После 15 находок открывается стол со всеми конвертами: можно выбрать письмо, прочитать и вернуться к нему позже. Содержание пока черновое, реальные подарки и номера упаковки не назначены.

## Запуск

Нужен Node.js 20.19+ или 22.12+.

```sh
npm install
npm run dev
```

Открыть `http://127.0.0.1:5173/` в браузере на этом компьютере. Сервер слушает только локальный адрес, сайт не опубликован. Шрифты и графика загружаются из проекта, внешних сервисов во время игры нет.

```sh
npm run build
npm test
```

Первый вызов проверяет TypeScript и создаёт статическую сборку `dist/`. Второй запускает проверки правил игры, сохранения и содержания. `npm run preview` позволяет посмотреть готовую сборку локально по адресу, который напечатает сервер.

Основное целевое устройство — iPhone 15 Pro с Safari. Для повторной проверки WebKit:

```sh
npx playwright install webkit
npm run test:iphone
```

Профиль устройства использует 393×659 доступных CSS-пикселей при открытых панелях Safari и плотность 3×; дополнительно проверяются полный экран 393×852, безопасные отступы, длинное письмо с увеличенным текстом, поворот и уменьшенная анимация. При горизонтальном положении сохраняется вертикальная композиция с обычной прокруткой страницы. Проверки не заменяют финальный проход на физическом iPhone с конкретной версией iOS.

### Открыть на настоящем iPhone по Wi-Fi

Подключить Mac и iPhone к одной домашней сети и выполнить:

```sh
npm run preview:phone
```

Команда собирает актуальный сайт, запускает готовую сборку на порту 4173 и показывает сетевой адрес с QR-кодом. Изображение QR сохраняется в `phone-preview.local/qr.png`, адрес — в `phone-preview.local/address.txt`. Открыть QR на Mac, считать камерой iPhone и перейти в Safari. Локальные файлы с адресом не попадают в Git или сборку; библиотека QR нужна только разработчику. Оставить команду работающей на время проверки; остановка — Ctrl+C. После смены сети повторить запуск, чтобы обновить адрес и QR.

Это временный доступ в локальной сети. Прогресс по этому адресу независим от `127.0.0.1:5173` и будущего адреса размещения; переносить его через JSON в настройках. Пошаговый проход и форма результата: [docs/qa/physical-iphone.md](docs/qa/physical-iphone.md). Постоянный QR для коробки готовится после размещения сайта.

Для автоматической проверки именно готовой сборки:

```sh
npm run test:iphone:build
```

Проверка сама собирает сайт и запускает отдельный сервер на `127.0.0.1:4183`, затем останавливает его. Выполняются 20 сценариев WebKit с обычной и уменьшенной анимацией: полный поиск, чтение, восстановление, повреждённые данные, ошибки и задержки загрузки, воспроизведение музыки и повтор после сетевой ошибки. Тест длинного готового письма остаётся в `npm run test:iphone`: он подменяет JSON-модуль только в режиме разработки, не меняя авторский файл.

## Музыка

Нота справа сверху включает и выключает зимнюю инструментальную мелодию без слов. При первом входе и после перезагрузки музыка выключена; файл загружается только по нажатию. В комнатах, у стола и внутри писем играет один плеер. При сворачивании страницы музыка останавливается; для продолжения нужно снова нажать ноту. При ошибке загрузки можно повторить нажатие, поиск продолжает работать.

`public/audio/winter-house.m4a` — оригинальная мелодия, синтезированная для проекта: мягкие клавиши и колокольчики, 80 секунд по кругу, около 0,84 МБ. Сторонние записи и семплы не использованы. Партитура и синтезатор сохранены в `scripts/render-winter-music.mjs`; для повторного рендера нужен macOS с доступом к системному AAC-кодеку (`node scripts/render-winter-music.mjs`). Для обычной сборки рендер не нужен. Заменить музыку можно готовым AAC-файлом по тому же пути, затем пересобрать сайт.

У записи тихий уровень; итоговую громкость на iPhone регулируют кнопки телефона. Запуск сделан непосредственно по нажатию с обработкой отказа `play()`, согласно [MDN](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/play). Звучание, поведение при звонке и блокировке экрана нужно дополнительно проверить на физическом iPhone: автоматический WebKit не подтверждает качество звука и все системные прерывания iOS.

## Где менять содержание

- `content/advent.json` — рабочий файл, который читает приложение: 15 постоянных ID. Письма №1–10 утверждены и связаны со свёртками №1–10; остальные пока черновики.
- `content/gifts.json` — авторский реестр подарков: названия, категории, описания, статусы и номера свёртков. Сейчас определено 10 подарков из 15: 7 куплено, 3 выбрано без подтверждённой покупки. №10 — сертификат на прокол уха. Реестр не подключён к интерфейсу приложения.
- `content/prototype.json` — сохранённый пример первого прототипа с условным № 12; приложение его больше не использует.
- `content/advent.example.json` — исходный шаблон.
- `src/scenes/house.ts` — комнаты, координаты предметов, тайники и подсказки. Каждый тайник ссылается на постоянный `letterId`.

Поля описаны в `IMPLEMENTATION_PLAN.md`. `paragraphs` — массив абзацев, `signature` — массив строк подписи, `packageNumber` — номер упаковки, `pickupNote` — необязательное указание, где забрать сюрприз. Текст отображается как обычный текст, HTML в данных не выполняется.

Содержание встроено в сборку. В режиме разработки Vite подхватит изменения автоматически; после публикации для обновления понадобится новая сборка. Не менять `id` уже используемых писем при редактуре текста.

Перед окончательным вручением можно проверить заполнение полного календаря:

```sh
npm run check:content
```

Сейчас эта команда ожидаемо сообщит о незаполненных черновиках. Она требует 15 готовых писем, уникальные номера упаковки 1–15 и уникальные ссылки на позиции авторского реестра. Готовность черновика не означает покупку подарка; программа не изменяет реестр.

## Прогресс

Хранится в `localStorage` текущего браузера и адреса, отдельно от JSON. Ключ полного дома — `dasha-winter:house-15:v2`. Старый ключ `dasha-winter:prototype-one-letter:v1` не читается и не меняется: одна демонстрационная находка не засчитывается в полный поиск. Отдельно сохраняются текущая комната, открытые тайники, находки, чтение и распаковка. После завершения поиска повторный вход ведёт к столу.

В настройках (значок справа сверху) можно начать заново с подтверждением. Сбрасывается только сохранение полного дома. Отметка распаковки доступна для готового письма с номером упаковки; её можно отменить непосредственно в письме. Черновики показываются явно и не предлагают отметить распаковку не назначенного подарка. При повреждении сохранения оригинал не перезаписывается: в настройках доступно скачивание исходных данных. При запрете хранилища игра работает в текущем сеансе и предупреждает об отсутствии сохранения; текущий сеанс можно экспортировать в файл.

Для переноса между устройствами: настройки → «Сохранить прогресс в файл» → сохранить JSON в «Файлы» на iPhone. На другом устройстве открыть сайт → настройки → «Восстановить из файла». Сначала показываются дата копии и сравнение количества находок, прочитанных писем и распаковок. Данные заменяются только по кнопке «Заменить прогресс»; можно отменить или предварительно скачать текущую копию. После восстановления незавершённый поиск открывается в сохранённой комнате, завершённый — за столом.

В копию входят только игровой прогресс и дата экспорта: без текстов писем, подарочного реестра и настроек устройства. Формат копии `dasha-winter-progress`, версия 1, вложенный игровой формат v2. Файл до 128 КБ проверяется на версию, набор ID, даты и согласованность событий. Повреждённый или неподходящий файл ничего не заменяет. Если браузер не даёт записать восстановление, текущий прогресс сохраняется без изменений. Старый прототип остаётся нетронутым. Это ручной перенос: автоматической синхронизации между устройствами нет.

После поиска кнопка «К столу с письмами» запускает короткое приближение к столу, мягкое зажигание света и раскладывание конвертов. Переход можно пропустить кнопкой «Перейти к письмам»; при системном уменьшении анимации он пропускается автоматически. При повторном входе, восстановлении файла или возврате из письма стол доступен сразу.

## Графика

- `public/assets/room-clean.png` — фон уголка без текста, конвертов и интерактивных предметов; `room.png` сохранён как исходник.
- `public/assets/desk.png` — стол без текста и писем.
- `public/assets/cushion.png` — отдельная подушка с прозрачным фоном.
- `public/assets/tree-clean.png`, `study-clean.png` — новые комнаты: ёлка и кабинет, очищенные от неподвижных дублей подвижных предметов. `tree.png` и `study.png` — исходники.
- `public/assets/props-atlas.png` — прозрачный атлас девяти рисованных предметов; из него получены отдельные подвижные слои.
- `docs/design/game-assets.json` — исходные промпты и ссылки на референсы; встроенный инструмент `image_gen.imagegen`.
- `docs/design/house-assets.json` — промпты второго этапа, устройство слоёв и соответствие тайникам.
- `docs/design/clean-backgrounds.json` — промпты очистки фонов для подвижных предметов.
- `docs/design/mockups/` — одобренные визуальные ориентиры.

Конверты, бумага, надписи и элементы управления сделаны в HTML/CSS/SVG. Предметы — отдельные прозрачные изображения: после нажатия слой сдвигается, появляется конверт, после находки он исчезает. Фоны остаются иллюстрацией, декоративные детали сами по себе не являются тайниками.

В браузер загружаются только WebP, нужные для текущей сцены: все игровые изображения вместе около 1,38 МБ, первая комната около 0,43 МБ. Исходные PNG сохранены для редактирования. Для повторной подготовки WebP и нарезки атласа:

```sh
npm run optimize:assets
```

Оптимизация использует `sharp` только при разработке; в браузере эта библиотека не загружается.

Результаты полного прохода — в `docs/qa/house-verification.md`; переход и перенос прогресса — в `docs/qa/desk-transfer-verification.md`; историческая проверка первого прототипа — в `docs/qa/prototype-verification.md`. `npm run test:iphone` проверяет полный поиск, чтение, безопасные отступы, длинный текст, поворот, переход и перенос прогресса в WebKit с профилем iPhone 15 Pro, с обычной и уменьшенной анимацией.
